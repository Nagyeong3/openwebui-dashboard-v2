# 보고 지표 및 진행률 업데이트 (2026-11-16)

## 반영 기능

- 질문 분류 및 운영 화면의 분류 진행률: 백분율, 처리/대상 건수, 모델 요청, 결과 재사용. 원본 확인 필요는 성공 분류와 별도로 표시.
- 팀장 순위: 질문 수 기준. 직전 동일 길이 기간과 기본 비교하며 비교 기간을 별도 지정할 수 있음. 비교 기간은 현재 조회 기간 이전이어야 함. 공동 순위(1,1,3) 사용. ▲ 상승, ▼ 하락, 유지, 이전0건→현재사용은 신규 사용. 사용량0인 팀장도 명부에서 유지. 이전 이력이 확인되지 않으면 증감을 만들지 않음.
- 양 기간 모두 현재 OpenWebUI 명부와 현재 조직 CSV로 비교. 과거 조직/직급 스냅샷을 복원한 인사 변동 분석이 아님. 기간 길이가 다르면 표시. 전체 기간은 기본 비교 없음.
- 개요와 토큰 화면의 총 토큰: K/M 축약 표시. 마우스 호버/키보드 포커스의 툴팁으로 정확값 제공.
- 최근30일 사용 사용자: 선택 종료일(전체기간은 마지막 수집일)까지 30일 동안 질문1건 이상인 고유 사용자. 일일 평균은 일별 고유 사용자 합계/30으로 사용0일도 포함. 로그인 접속 기록이 아닌 질문 활동 지표이며 수집된 이력 기준.
- 주간 모델 응답 추이: role=assistant로 저장된 고유 메시지 건수. 질문, 임베딩, LiteLLM 호출 건수와 다름. 한국 시간 월요일~일요일, 선택 기간 밖 응답은 제외. 첫/마지막 일부 주는 * 표시. 기간 총계 및 최고 주간 건수 제공. 저장된 분기/재생성 메시지도 포함할 수 있음.
- 개요 CSV 및 사용자 탭 팀장 CSV에 순위 비교 정보 포함. 기존 실행 이력 내보내기는 추가하지 않음.

## 운영 서버 적용

1. 진행 중인 운영 업데이트/분류를 안전하게 중단하고 대시보드 서버를 Ctrl+C로 종료.
2. 기존 코드와 실제 .env, DB, CSV를 백업. DB는 서버 종료 후 복사.
3. ZIP의 backend_v2 전체 및 frontend_v2/dist 전체를 운영 프로젝트의 같은 위치에 교체. 백엔드 reporting.py도 반드시 포함.
4. 실제 .env, data와 기존 CSV, Conda 환경은 그대로 유지. .env.example은 설명용이며 실제 .env를 덮어쓰지 않음. 프런트 소스도 frontend_v2에 동봉했지만 운영에는 dist만 필요.
5. 기존 환경을 활성화하고 프로젝트 루트에서 실행:

```bat
conda activate oui-dashboard-v2
cd /d D:\project\oui-dashboard-v2
python -m uvicorn backend_v2.app:create_app --factory --host 0.0.0.0 --port 8011 --workers 1
```

6. Ctrl+F5. /api/dashboard/v2/auth/status가 JSON인지 확인. 개요 최근30일 사용자, 주간 응답 총계, 팀장 순위의 이전순위/증감을 확인.
7. 사용자 탭 팀장만 보기에서도 비교 기간을 지정하여 순위 확인. 질문 분류 진행률은 실제 분류를 실행할 때 확인.

새 패키지 설치, 전체 재수집 또는 전체 재분류는 필요하지 않음. 데이터가 오래됐다면 운영 화면의 일반 업데이트를 실행. 중단/재개된 실행과 원천 연결은 사내 서버에서 검수. 문제 발생 시 서버를 종료하고 백업한 코드로 복구.

## 검증

백엔드111개, 프런트33개 자동 테스트 및 TypeScript/API 빌드 통과. 합성 데이터 HTTP 통합 검증(맞춤 비교기간, 전체팀장/페이지독립성, CSV, 오류422), 공동순위/신규사용/과거이력없음, 한국시간 경계, 주간 합계와 일부주, 30일 중복제거/0일포함 검증. 실제 폐쇄망 원천과 시각적 화면 검수는 미완료. 브라우저 자동 실행은 환경의 socket 권한 제한으로 실패하여 통과로 기록하지 않음.
